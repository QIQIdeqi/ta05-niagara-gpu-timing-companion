Why does one Niagara cache track return to the first frame?

This UE 5.8.4 test used one CPU emitter. Both Sequencer sections use a 60 fps display rate, Repeat playback and the display-frame range [0,59). The internal tick resolutions are 24,000 and 60 ticks per second. A disables interpolation and B enables it.

At 24,000 ticks per second the sampled positions match the first cache frame. At 60 ticks per second the request exceeds this cache’s end age and the component completes. This result applies to the recorded cache, section and Repeat settings. For Movie Render Queue output, check the engine log and the actual output frame numbers separately.

Recreate the comparison in your own Unreal project

  1. In UE 5.8.4, enable Niagara Sim Caching and start with one CPU emitter. For the original capture, one fixed-seed simulation produced two 59-frame caches from source steps 2 through 60 at a 1/60-second step. Keep the seed, transform, recorded attributes and recording range fixed. Disable velocity extrapolation, rebasing and data-interface caching in both. Capture A with interpolation off and B with it on. Verify that the recorded endpoint positions and UniqueIDs agree before interpreting subframe differences.
  2. Bind the level’s Niagara component in Sequencer and add a Niagara Cache track. Set the display rate to 60 fps, section range to [0,59), playback to Repeat and section offset to zero. Allow subframe evaluation. Create two sequence variants with internal tick resolutions of 24,000 and 60 ticks per second. After changing the resolution, check that the displayed frame rate and section range still match.
  3. In each sequence, compare frames 57 and 58 in the viewport. To request 57.99 precisely, use the Level Sequence Player’s SetPlaybackPosition with a fractional display-frame time, then read the Niagara component’s Desired Age set by the track. Record the requested age, Active/Complete status and position count for each condition. Repeat with both cache variants. Save and reopen the level before checking the bindings again.

If your results differ, first check the component binding, assigned cache, recording start and end ages, and Repeat section boundaries. A blank viewport alone cannot establish that a component completed. Your own recording can have different boundary ages. The exact numeric answer above comes from the fixed-step capture, while the editor steps let you compare the behavior in your project.

For a separate MRQ check, hold the camera, output rate and shutter fixed. Compare the engine log and emitted frame numbers before comparing pixels. Record temporal sampling separately from Sequencer’s display rate and internal tick resolution.
